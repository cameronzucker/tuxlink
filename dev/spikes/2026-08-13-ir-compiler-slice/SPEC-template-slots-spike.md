## Components

1. **Real routines port in `tuxlink-mcp-testserver`.** Replace the canned
   `MockRoutines` wiring with a port backed by the real `tuxlink-routines`
   registry catalog, real validator, and a temp-dir (or in-memory) store.
   Routine EXECUTION stays out of scope — this spike tests the authoring
   surface; `routines_run` may remain inert. Kills the mock-response
   contamination class for good.
2. **Intake tool, testserver-only:** `routine_template_compile`. Input:
   `{template: string, slots: object}`. Output on success: the compiled
   real `RoutineDef` + the plain-language readback (existing renderer).
   Output on failure: named, positioned refusals (unknown template,
   unknown slot, malformed value — each names the offending key). The tool
   registers ONLY in the testserver router: the model observes a 96-tool
   surface where the sheet's compiler genuinely exists; the product binary
   and parity manifest are untouched.
3. **The compiler.** Registry: `scheduled-connect-with-fallback` (the
   ratified sheet's template) plus 2–3 DISTRACTOR templates (plausible,
   semantically distinct — e.g. a beacon-schedule template and a
   log-rotation template; drafted in the PLAN, reviewable). Expansion:
   `every`/`window` → the real `Trigger` schedule (window is native);
   `bands` order → connect lowering; `success_log`/`failure_log` →
   log steps referencing the connect step's declared outputs; `fail_reason`
   → the end control. Deterministic ids generated by the compiler. Golden
   unit tests from the banked asks (the wa-gateways ask, the nv-gateways
   pressure ask, both edit asks, the correction ask).
4. **Matrix v2.** Cells per the prior instrument — N1, N2, E1, E2, C1 —
   plus NEW selection cells S1/S2 (the ask against the distractor-bearing
   registry; correct template pre-registered), plus CTRL (no sheet),
   2 samples per cell. Emission = the intake tool call (resolves placement
   by construction). Capture verbatim as before.

## Pre-registered grading

Primary mechanical grader = **the compiler itself**: accept/refuse verdict
+ compiled-def semantic checks (values against the ask, pre-registered per
cell as before). Secondary: trace assertions (mutating routine-tool calls
= defection, expected 0; intake-tool usage expected 1 per run). Eyeball row
mandatory, per standing discipline.

## Acceptance criteria (falsifiable; defaults chosen, operator may adjust)

**PASS** requires ALL of:
- ≥90% of N/E/C runs end in a compiler-ACCEPTED artifact whose values are
  ask-correct (the per-cell semantic checks).
- Zero defections to mutating native routine tools across sheet cells.
- ≥80% correct template selection on the distractor cells.
- Refusal channel holds: under the N2 inexpressible pressure, refusals
  arrive as prose or as compiler refusals — free-text-slot smuggling in
  MORE than 2 of the matrix's runs is a FAIL of the refusal-channel
  design (1–2 occurrences = recorded finding feeding the evaluation).

**FAIL** on any criterion → the ruling brief lays out the failure shape;
whether the five-construct challenger gets built is a NEW operator
decision, never automatic.
